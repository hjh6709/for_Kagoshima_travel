# 공유 여행 화면과 실제 지도 경험 개선 설계

- 작성일: 2026-07-29
- 상태: 사용자 승인
- 대상: 모바일 PWA의 여행 소유자 지도 탭과 공개 공유 여행 화면

## 1. 배경

현재 여행의 장소 검색 결과에는 위도와 경도가 저장되지만, 지도 탭은 실제 지도가 아니라 장소와 이동 정보를 나열하는 화면에 가깝다. 사용자는 검색해 추가한 장소가 정확한 위치에 저장되었는지 앱 안에서 확인하기 어렵고, 현재 위치와 다음 방문 장소 사이의 관계도 한눈에 파악할 수 없다.

공개 공유 여행 화면은 일정, 항공편, 장소, 이동 정보, 체크리스트가 하나의 긴 페이지에 이어진다. 동행자는 읽기 전용 정보만 필요하지만, 현재 구조에서는 오늘 필요한 정보와 지도, 전체 여행 정보를 빠르게 구분하기 어렵다.

앱 내부 지도와 실제 내비게이션의 역할도 분명히 나눌 필요가 있다.

- 앱 내부 지도: 현재 위치와 저장 장소의 공간 관계 확인
- 외부 지도 앱: 실제 경로 탐색과 이동 안내

## 2. 목표

1. 검색해서 추가한 장소의 좌표를 앱 내부 지도 핀으로 확인할 수 있다.
2. 사용자가 원할 때 현재 위치와 저장 장소를 같은 지도에서 볼 수 있다.
3. 저장 장소 핀과 장소 목록이 하나의 선택 상태로 동작한다.
4. 길찾기는 기존 고덕지도와 Google 지도 연결을 유지한다.
5. 일정 탭은 시간 중심, 지도 탭은 공간 중심이라는 차이를 명확하게 만든다.
6. 공유 화면을 `오늘`, `지도`, `여행정보`로 나누어 동행자가 필요한 정보를 빠르게 찾게 한다.
7. 지도나 위치 기능이 실패해도 장소 목록과 외부 길찾기는 계속 사용할 수 있다.

## 3. 비목표

- 앱 내부에서 턴바이턴 내비게이션을 구현하지 않는다.
- 현재 위치를 서버나 데이터베이스에 저장하지 않는다.
- 사용자가 위도와 경도를 직접 입력하게 하지 않는다.
- 이번 변경을 위해 새 장소 API나 데이터베이스 구조를 만들지 않는다.
- 고덕지도 JavaScript SDK를 새로 연동하지 않는다.
- 오프라인 지도 타일 다운로드 기능을 만들지 않는다.

## 4. 선택한 접근법

앱 내부 지도는 Google Maps JavaScript API를 지연 로딩하고, 현재 위치는 브라우저 Geolocation API로 얻는다. 저장 장소는 기존 `latitude`, `longitude`, `googlePlaceId` 데이터를 재사용한다.

Google 지도는 앱 안에서 위치를 확인하는 역할만 담당한다. 실제 길찾기는 현재와 동일하게 외부 고덕지도 또는 Google 지도에 위임한다.

이 접근법을 선택한 이유는 다음과 같다.

- 기존 장소 검색 결과의 좌표 체계와 일관된다.
- 전 세계 여행이라는 제품 범위에 맞는다.
- 여러 핀, 선택 핀, 지도 범위 조정 같은 기본 동작을 안정적으로 지원한다.
- 새 API나 DB 마이그레이션 없이 구현할 수 있다.

중국에서 Google 지도가 로드되지 않을 가능성은 명시적인 실패 상태로 다룬다. 이때 기존 장소 목록과 고덕지도 검색·길찾기 연결을 유지하여 핵심 이동 기능을 보존한다.

## 5. 정보 구조

### 5.1 여행 소유자 화면

#### 일정 탭

시간의 흐름과 실행할 일을 중심으로 구성한다.

- 오늘 일정
- 다음 일정
- 시간과 완료 상태
- 오늘 필요한 체크 항목

지도 전체나 모든 장소 카드는 반복해서 노출하지 않는다.

#### 지도 탭

장소의 공간 관계와 이동 결정을 중심으로 구성한다.

- 실제 지도
- 저장 장소 핀
- 현재 위치 표시 버튼
- 선택한 장소의 하단 상세 카드
- 장소 목록
- 고덕지도·Google 지도 길찾기 선택

### 5.2 공개 공유 여행 화면

한 페이지 안에 모바일용 구분 내비게이션을 제공한다.

#### 오늘

- 여행 상태와 날짜
- 오늘 일정
- 오늘 필요한 읽기 전용 체크 항목

#### 지도

- 저장 장소 지도 핀
- 사용자가 요청한 경우 현재 위치
- 장소 목록과 선택 장소 카드
- 외부 지도 길찾기

#### 여행정보

- 전체 일정
- 항공편
- 이동 정보
- 전체 읽기 전용 체크리스트

공유 화면에서는 수정, 삭제, 완료 처리 같은 소유자 동작을 제공하지 않는다.

## 6. 지도 상호작용

### 6.1 최초 상태

- 유효한 좌표가 있는 저장 장소 핀을 즉시 표시한다.
- 모든 저장 장소가 보이도록 지도 범위를 자동 조정한다.
- 현재 위치 권한은 자동으로 요청하지 않는다.
- 좌표가 없는 장소도 목록에서는 유지한다.

### 6.2 현재 위치

- 사용자가 `현재 위치 표시` 버튼을 눌렀을 때만 권한을 요청한다.
- 권한이 허용되면 현재 위치를 저장 장소 핀과 함께 표시한다.
- 현재 위치를 포함하도록 지도 범위를 다시 조정한다.
- 현재 위치는 프론트엔드 메모리에만 두며 API로 전송하지 않는다.
- 지속적인 위치 추적은 사용하지 않는다. 사용자가 다시 요청할 때 위치를 갱신한다.

### 6.3 핀과 목록의 연결

- 핀을 누르면 같은 장소가 선택되고 하단 상세 카드가 열린다.
- 목록에서 장소를 누르면 해당 핀으로 지도가 이동한다.
- 선택한 핀은 시각적으로 구분한다.
- 상세 카드에는 장소명, 주소, 방문일 또는 일정 정보, 길찾기 버튼을 표시한다.
- 지도 위에 많은 정보를 중복 표시하지 않고 선택 카드에 집중한다.

### 6.4 길찾기

- 중국 여행은 고덕지도와 Google 지도 중에서 선택할 수 있다.
- 그 외 지역은 Google 지도를 기본으로 제공한다.
- 좌표 체계 불일치 가능성이 있는 Google Places 장소를 고덕지도로 넘길 때는 기존 방식대로 현지 이름과 주소 검색을 우선한다.
- 앱 내부 지도 로딩 여부와 무관하게 외부 길찾기 버튼은 동작해야 한다.

## 7. 컴포넌트 설계

실제 지도 표현은 소유자 지도 탭과 공유 화면이 함께 사용하는 프레젠테이션 컴포넌트로 분리한다.

예상 책임은 다음과 같다.

### `TravelMap`

- 지도 SDK 지연 로딩
- 유효한 장소 좌표를 핀으로 렌더링
- 현재 위치 렌더링
- 지도 범위 자동 조정
- 핀 선택 이벤트 전달
- 로딩·오류·오프라인 상태 표시

### `MapPlaceSheet`

- 선택 장소 요약
- 장소 목록과 동일한 선택 상태 사용
- 외부 길찾기 진입점 제공

### 기존 `MapDirectionsChoice`

- 고덕지도와 Google 지도 선택 로직 유지
- 새 지도 컴포넌트에서 재사용

### 화면 컨테이너

- 소유자 지도 탭은 편집 가능한 여행 데이터와 선택 상태를 관리한다.
- 공유 화면은 마스킹된 공개 데이터만 전달하고 읽기 전용 동작만 제공한다.
- 지도 컴포넌트는 소유권이나 편집 권한을 판단하지 않는다.

## 8. 데이터 흐름

1. 기존 여행 또는 공유 여행 API가 장소 목록을 반환한다.
2. 화면 컨테이너가 유효한 위도·경도를 가진 장소와 좌표가 없는 장소를 구분한다.
3. `TravelMap`은 유효한 장소만 핀으로 렌더링한다.
4. 모든 장소는 좌표 유무와 관계없이 목록에 표시한다.
5. 사용자 동작으로만 현재 위치를 요청한다.
6. 핀 또는 목록 선택 결과를 화면 컨테이너의 단일 선택 상태에 반영한다.
7. 길찾기 선택 시 기존 외부 지도 URL 생성 로직을 사용한다.

새 API 요청이나 DB 쓰기는 추가하지 않는다.

## 9. 오류 및 대체 동작

### 지도 SDK 로딩 실패

- 지도 영역에 간결한 오류 안내와 다시 시도 버튼을 표시한다.
- 장소 목록과 외부 길찾기는 그대로 유지한다.

### 위치 권한 거부

- 저장 장소 핀은 계속 표시한다.
- 현재 위치 버튼 주변에 권한이 필요하다는 짧은 안내를 제공한다.
- 권한 요청을 반복적으로 자동 실행하지 않는다.

### 위치 확인 실패 또는 시간 초과

- 다시 시도 버튼을 제공한다.
- 오래된 위치를 서버에서 복원하거나 영구 저장하지 않는다.

### 좌표 누락 또는 잘못된 좌표

- 해당 장소는 핀에서 제외한다.
- 목록에는 `위치 정보 없음` 상태로 표시한다.
- 이름이나 주소가 있다면 외부 지도 검색 연결은 유지한다.

### 오프라인

- 캐시된 여행 및 장소 목록을 우선 보여준다.
- 실시간 지도를 사용할 수 없음을 지도 영역에 표시한다.
- 네트워크가 복구되면 사용자가 다시 시도할 수 있다.

### 중국 내 Google 지도 사용 불가

- 지도 실패 상태를 일반적인 장소 없음 상태로 오인시키지 않는다.
- 장소 목록, 현지 이름, 주소와 고덕지도 연결을 유지한다.

## 10. 보안과 개인정보

- 브라우저 지도 키는 서버용 Places 키와 분리한다.
- 브라우저 키는 허용 도메인과 Maps JavaScript API로 제한한다.
- 실제 키 값은 저장소에 커밋하지 않는다.
- 현재 위치는 API, 로그, 분석 이벤트, DB에 포함하지 않는다.
- 공유 화면은 기존 공개 응답의 마스킹 정책을 유지한다.
- 공개 화면에 여행 메모나 민감한 항공·일정 메모를 새로 노출하지 않는다.

## 11. 접근성과 모바일 UX

- 현재 위치와 길찾기 버튼은 최소 터치 영역을 확보한다.
- 핀 선택만으로 정보를 전달하지 않고 목록에서도 동일한 장소에 접근할 수 있게 한다.
- 선택 핀은 색상뿐 아니라 크기나 외곽선으로 구분한다.
- 지도 제스처가 페이지 전체 스크롤을 막지 않도록 지도 높이와 하단 카드 동작을 제한한다.
- 작은 화면에서 하단 카드가 지도 핵심 영역을 모두 가리지 않게 한다.
- 위치 권한과 지도 오류 문구는 사용자가 다음에 할 행동을 알 수 있게 작성한다.

## 12. 검증 계획

### 자동 검증

- 유효 좌표와 잘못된 좌표 필터링
- 장소 선택 상태와 핀·목록 동기화
- Google 지도와 고덕지도 URL 생성
- 공유 화면에서 편집 동작이 노출되지 않음
- 공개 응답의 민감정보 마스킹 회귀
- 웹 타입 검사와 프로덕션 빌드

### 수동 모바일 검증

- 360px, 390px, 430px 폭
- 장소 0개, 1개, 여러 개
- 동일하거나 매우 가까운 장소
- 좌표가 없는 장소
- 현재 위치 권한 허용, 거부, 시간 초과
- 온라인에서 오프라인으로 전환 후 복구
- 지도 SDK 로딩 실패
- 핀 선택과 목록 선택의 양방향 동기화
- 중국 장소의 고덕지도 연결
- Google 지도 길찾기 연결
- 공개 공유 링크의 비로그인 접근

## 13. 완료 조건

- 검색해 저장한 장소가 정확한 지도 핀으로 나타난다.
- 현재 위치를 요청하면 저장 장소와 같은 지도에서 볼 수 있다.
- 핀과 장소 목록이 일관되게 선택된다.
- 지도 실패 상태에서도 장소 목록과 외부 길찾기를 사용할 수 있다.
- 일정 탭과 지도 탭의 정보 목적이 명확히 구분된다.
- 공유 여행 화면에서 `오늘`, `지도`, `여행정보`를 빠르게 오갈 수 있다.
- 새 API나 DB 마이그레이션 없이 기존 좌표와 길찾기 로직을 재사용한다.

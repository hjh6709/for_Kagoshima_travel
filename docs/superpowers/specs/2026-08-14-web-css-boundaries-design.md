# 웹 CSS 책임 분리와 점진적 격리 설계

## 배경

현재 웹 앱은 `styles.css`에서 전역 CSS 파일을 정해진 순서로 불러오고, 마지막의
`theme-ios.css`가 여러 화면의 표현을 보정한다. 이 구조 자체는 동작하지만
`trip.css`가 1,845줄, `manage.css`가 1,730줄까지 커졌다. 특히 `trip.css`에는
공통 여행 화면, 마이페이지, 오늘 탭, 일정 탭과 폭별 미디어쿼리가 한 파일에 섞여 있다.

최근 195px 회귀처럼 한 화면의 규칙을 고칠 때 뒤쪽 덮어쓰기와 다른 폭의 미디어쿼리를
함께 추적해야 한다. 이번 작업의 목적은 디자인을 바꾸는 것이 아니라 스타일의 책임과
우선순위를 코드 구조에 드러내는 것이다.

## 목표

- 현재 UI, DOM, 사용자 동작과 접근성 의미를 그대로 유지한다.
- `trip.css`의 화면별 책임을 분리하되 기존 cascade 순서를 보존한다.
- 전역 스타일의 우선순위를 Cascade Layers로 명시할 수 있는 기반을 만든다.
- 경계가 명확한 화면부터 CSS Modules로 옮길 수 있는 이행 경로를 만든다.
- 195px, 320px, 375px와 200% 확대에서 가로 넘침과 레이아웃 회귀를 막는다.

## 비목표

- 색상, 타이포그래피, 여백 또는 컴포넌트 디자인을 다시 설계하지 않는다.
- `manage.css`를 같은 PR에서 분리하지 않는다.
- 모든 전역 클래스를 한 번에 CSS Modules로 바꾸지 않는다.
- 사용하지 않는 기존 클래스를 근거 없이 삭제하지 않는다.
- React 컴포넌트 구조나 데이터 흐름을 함께 리팩터링하지 않는다.

## 선택한 접근

### 1단계: cascade를 보존하는 기계적 파일 분리

기존 `trip.css`는 스타일 진입점으로 유지하고 다음 파일을 현재 등장 순서 그대로 불러온다.

1. `trip-core.css` — 공통 여행 화면, 버튼, 카드, 기본 타임라인
2. `trip-mypage.css` — 마이페이지와 계정 관련 여행 화면
3. `trip-narrow.css` — 현재 한 블록에 함께 있는 360px·240px 전역 보정
4. `trip-today.css` — 오늘 탭과 다음 일정 hero
5. `trip-schedule.css` — 일정 탭, 날짜 pill, 일정 카드와 준비 체크리스트

분리 경계는 현재 `trip.css`의 연속된 구간을 기준으로 한다. 특히 마이페이지 뒤의 240px
미디어쿼리에는 공통·오늘·일정 규칙이 함께 있으므로 1단계에서는 이를 억지로 화면별로
재배치하지 않고 `trip-narrow.css`라는 연속 구간으로 보존한다. 셀렉터를 합치거나 선언 순서를
바꾸지 않는다. `styles.css`는 계속 `trip.css` 하나만 불러오므로 `map.css`,
`travel-components.css`, `theme-ios.css`와의 상대적인 순서도 유지된다.

CSS 내용을 직접 읽는 계약 테스트는 새 파일을 명시적으로 읽거나, 테스트 전용 헬퍼가
여행 스타일 묶음을 순서대로 결합하도록 변경한다. 테스트가 구현 파일 하나에 묶이지 않고
실제 스타일 인터페이스를 검사하게 한다.

### 2단계: Cascade Layers로 전역 우선순위 명시

1단계가 렌더 차이 없이 통과한 뒤 별도 PR에서 전역 스타일을 다음 계층으로 선언한다.

```css
@layer tokens, foundation, features, feedback, theme;
```

- `tokens`: 폰트와 디자인 토큰
- `foundation`: reset, 공통 레이아웃과 기본 컨트롤
- `features`: manage, trip, map, share와 여행 도구
- `feedback`: toast, 오류와 네트워크 상태
- `theme`: 의도적으로 feature 표현을 덮는 최종 테마

계층 도입 전후의 계산 스타일을 비교한다. 계층을 추가하는 과정에서 기존 우선순위가 달라지는
규칙은 추측으로 고치지 않고 테스트 또는 실제 렌더로 확인한 뒤 명시적인 계층 안으로 옮긴다.

### 3단계: CSS Modules의 점진적 적용

전역 스타일 전체를 변환하지 않는다. 다음 조건을 모두 만족하는 컴포넌트부터 한 PR에 하나의
작은 화면 묶음만 옮긴다.

- 하나의 React 컴포넌트 또는 가까운 하위 컴포넌트만 사용하는 클래스다.
- `theme-ios.css`나 다른 화면이 해당 클래스를 직접 덮지 않는다.
- JavaScript에서 문자열로 클래스 이름을 조합하거나 검색하지 않는다.
- 접근성 계약과 반응형 동작을 독립적으로 검증할 수 있다.

첫 후보는 일정 카드 묶음이다. 다만 사전 검색에서 공유 전역 규칙이나 테마 덮어쓰기가 발견되면
더 독립적인 작은 컴포넌트로 후보를 바꾼다. 디자인 토큰과 공용 버튼 같은 스타일은 전역에 남긴다.

## 인터페이스와 책임

### 전역 스타일 인터페이스

호출자가 알아야 하는 것은 `styles.css` 하나다. 앱 진입점은 계속 이 파일만 import한다.
내부 파일 분리는 구현 세부사항이며 React 컴포넌트의 import 방식은 1단계에서 바뀌지 않는다.

### 기능 스타일 인터페이스

각 기능 파일은 자신이 담당하는 화면 클래스만 소유한다. 화면 사이에서 공유되는 토큰과 공통
컨트롤은 `tokens.css`와 `foundation.css`에 남긴다. 기능 파일이 다른 기능 파일의 내부 클래스를
덮어써야 한다면 CSS Modules 전환 전에 그 의존성을 문서화하고 해소한다.

### CSS Module 인터페이스

CSS Module로 옮긴 컴포넌트는 자신의 `styles` 객체만 사용한다. 다른 화면은 생성된 클래스명을
알거나 덮어쓰지 않는다. 공유되어야 하는 상태는 전역 클래스가 아니라 명시적인 props 또는
디자인 토큰으로 전달한다.

## 오류와 롤백

- 파일 누락이나 import 오류는 프로덕션 빌드 실패로 차단한다.
- 계약 테스트가 특정 파일 위치에 과도하게 의존하지 않도록 스타일 묶음 로더를 사용한다.
- 시각 차이가 발견되면 선언을 추가해 덮지 않고 해당 단계의 이동 또는 layer 적용을 되돌린다.
- 각 단계는 독립 PR이므로 문제가 생긴 단계만 revert할 수 있다.

## 검증 기준

각 단계에서 다음을 모두 만족해야 한다.

1. `npm --prefix apps/web test`
2. 접근성·의존성·모바일 CSS 계약 테스트
3. `npm run check`
4. Playwright E2E 스모크
5. 195px, 320px, 375px에서 `scrollWidth <= clientWidth`
6. 200% 확대에서 일정, 지도와 관리 폼이 한 열로 재배치됨
7. 로그인, 오늘, 일정, 지도, 항공, 긴급, 마이페이지 핵심 화면의 콘솔 오류 없음

1단계의 추가 성공 조건은 변경 전후 주요 요소의 계산 스타일이 같고 스크린샷 차이가 없는 것이다.
2단계는 layer 도입 전후 우선순위가 의도와 일치해야 한다. 3단계는 변환한 컴포넌트의 클래스가
전역 검색 결과에서 더 이상 외부 소비자를 갖지 않아야 한다.

## 작업 단위

- PR 1: `trip.css`의 연속 구간 분리와 계약 테스트 경로 개선
- PR 2: 전역 Cascade Layers 도입과 cascade 회귀 고정
- PR 3 이후: 검증된 작은 화면 단위의 CSS Modules 전환

각 PR은 리팩터링만 수행하며 시각 개선이나 기능 변경을 섞지 않는다.
